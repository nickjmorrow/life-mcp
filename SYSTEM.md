# life-mcp

The Life connector: one remote MCP server that connects an agent (claude.ai, Claude Code, anything that speaks MCP) to the software in Nicholas's life — Logseq, Apple Health and Hevy, Eight Sleep, Contacts and Messages, Reminders, Music and the HomePods, the Apple TV, Apple Home and Hue. This file covers the code; how his agent uses it lives in his private agent harness.

**This repo is public.** Nothing personal goes in it: no other people's names or details, health facts, addresses, hostnames, IP addresses, account or device IDs, plans or history. Personal settings come from the private folder (below), secrets from the environment. Tests use made-up people and places and documentation IPs (192.0.2.x).

## How it fits together

```
claude.ai (phone, web) ─┐                                  ┌─ Logseq graph (notes, journal), shared memory (files in git)
Claude Code ─────────────┼─► Tailscale Funnel ─► server/ ───┼─ health.db (Apple Health, Hevy, Eight Sleep)
other agents ───────────┘   (HTTPS, GitHub      (FastMCP,   ├─ Messages + Contacts copies (people)
                             sign-in, one        one Mac at  ├─ Hue, Eight Sleep, Reminders, Music/HomePods,
                             account)            home)       │  Apple TV, Apple Home (via home-app/)
                                                             ├─ skills (from the private folder)
                                                             └─ approvals service (gets proposals; applies nothing without a passkey)
```

## Parts

- **`server/`** — the connector. `server.py` builds one FastMCP server with GitHub OAuth (only the account in `LIFE_MCP_GITHUB_ID`, re-checked on every request), serves the Logseq tools itself, and mounts every tool group listed in its `GROUPS` table with `mount_all()` (a group that fails to import is logged and skipped): `memory_mcp.py` + `memory_store.py` + `context.py` (shared memory as files, and the context bundle; see below), `proposals_mcp.py` (rule and memory proposals; see below), `skills_mcp.py` (skills and their index), `health_mcp.py` + `health_import.py` (an hourly importer into SQLite), `people_mcp.py` + `people_data.py` (read-only copies of Messages and Contacts made by `people/people-snapshot.swift`, the only thing with Full Disk Access), `cards_mcp.py` (flashcard review; `page` and `chapter` filters, a chapter being the nearest ancestor heading `ch N - …`; `cards_next` carries the private flashcard-review skill in its description, via `skill_tools.py`, since claude.ai finds tools by tool search and often never loads a skill), `reminders_mcp.py`, `music_mcp.py` / `music_lib_mcp.py` (Music.app and HomePods; catalog, recommendations and history through `applemusic_api.py` with a MusicKit key and a user token from the one-time sign-in page `applemusic_signin.py` on `127.0.0.1:8770`, run on the Mac you're at and copied to the server Mac as a secret; catalog songs reach playlists through the library, since a script-made playlist doesn't sync until it has a song), `tv_mcp.py` (Apple TV via pyatv; screenshots via Xcode's devicectl), `home_mcp.py`, `eightsleep_proxy.py` (the npm Eight Sleep server) + `eightsleep_mcp.py`, `hevy_mcp.py` (Hevy's API with the key kept server-side). A new group is one line in `GROUPS` plus a check in `smoke.py` (a test keeps them in step). It listens on 127.0.0.1 only; Tailscale Funnel is the public door. `run.sh` starts it under launchd (`com.nicholai.life-mcp`). Messages name the Mac it runs on (`host.NAME`), never a fixed machine.
- **`server/cards_web.py`** — a phone page over the same flashcard deck as `cards_mcp.py` (scheduling in `fsrs.py`, FSRS v4 on Logseq's own properties): it reads each card aloud with the browser's speech synthesis and takes Again / Hard / Good / Easy. It listens on 127.0.0.1 (`CARDS_PORT`, default 8769; launchd via `cards-web.sh`), is meant for `tailscale serve` (never Funnel), refuses any Host that isn't local or in the private config's `cards_hosts`, and needs an `X-Cards` header to write, so other web pages can't drive it.
- **`server/api.py`** — the supported interface for other code on the same Mac (his private lessons job): `cli(*args, json_out=False)`, `edn`, `ensure_properties`, `target_args`, `memory()` (a shared-memory handle with the memory tools' rules) and `people_note`. **Import `api`, nothing else**: the rest of `server/` can change without notice. Run such code with `PYTHONPATH=<this repo>/server uv run --project <this repo>/server python …`.
- **`hue/`** — Philips Hue tools (CLIP v2), mounted by the server as `hue_*`.
- **`home-app/`** — Life Home, a signed Mac Catalyst helper with the HomeKit entitlement (HomeKit has no API for command-line tools). It serves a loopback API on 127.0.0.1:8767 that refuses web pages (Host must be local, no Origin) and any request without the shared secret: the connector makes `~/.config/life-mcp/home-token` (600) and sends it as `X-Life-Home-Token`; the sandboxed app reads that one file through a read-only sandbox exception (see `home-app/FINDINGS.md`).
- **Settings and skills** come from a private folder outside this repo (`server/private.py`; `LIFE_MCP_PRIVATE`): its `config.toml` (Logseq graph name, Apple TV address, time zone, health database path) and its `skills/`. Personal routing (which app answers which kind of request) belongs in his skills there, not in the connector's instructions, which stay generic and factual. Without it the code runs with neutral defaults. Secrets come from the environment. Skill text, and the skill index that `memory_recall` returns, are read from disk on every call, so an edit is live at once; only what's built when the service starts needs a restart: the per-skill MCP prompts, the instructions text sent to clients that read it, and the descriptions of tools that carry a skill (`skill_tools.py`).

## Memory, the context bundle and proposals

- **Shared memory is files, not a Logseq page.** `memory_store.py` keeps Markdown topic files in a local git repo (`memory_dir` in the private config, default `~/Library/Application Support/life-mcp/memory`): `core.md` (the few facts that change most answers, at most 2,500 characters), `topics/<name>.md`, `archive.md` (facts that ended: never loaded, found by asking for it by name) and `.ids.json`. An entry is one line with an id (`- [h12] text (2026-09-27, phone)`); ids never change, even when an entry moves, and are never used twice. Every write is one git commit made under an exclusive lock, so a chat and a job writing at the same moment can't lose each other's changes or share an id. A save that is 0.6 similar to an entry already there is held until the caller says `similar="add"` or `similar="replace:<id>"`; an exact repeat is skipped. `memory_mcp.py` is the three tools (`memory_recall`, `memory_save`, `memory_update`) and the guard in front of every text that enters memory; other code on the same Mac reaches the store through `api.memory()`.
- **The context bundle** (`context.py`) is the one text every surface loads at the start of a conversation: the rules (`RULES.md` in the private folder), the core facts and one line per topic. It is built on the server and saved as `bundle.md` in the memory repo, rebuilt inside the commit of every memory write, so git shows exactly what Claude was told on any day. `memory_recall` with no topic returns it followed by the skills' index (read fresh each time); the laptop and the voice assistant read the same file. Such a recall can itself commit a rebuilt bundle (it's derived data) when `bundle.md` is missing, or `RULES.md` or the memory repo changed since it was last committed. That commit takes in everything in the memory folder (`git add -A`), so a hand edit rides along under "memory: rebuild bundle". `python context.py --write` rebuilds it, and `--print phone|laptop|hob` shows what a surface loads. The limits are checked and logged, never enforced (a rule that quietly vanished would be worse): rules 4,000 characters, the whole bundle 9,000 (Claude Code cuts a hook's output at 10,000).
- **Every process that opens the memory store must run with `LIFE_MCP_PRIVATE` pointing at the approved copy of the private folder**, the one whose `RULES.md` the user has reviewed, not a working checkout. The bundle is rebuilt from `<private>/RULES.md`, so a process pointed at unreviewed text would put it in the bundle every surface reads.
- **Proposals** (`proposals_mcp.py`). `rule_propose` (an edit to a rules or skills file) and `memory_propose` (update, remove, archive or save a memory entry) post the proposal to the approvals service, a local web service in the private harness that checks it, shows the user the exact change, and applies it only after he approves it with a passkey. They only ask: nothing here changes a rule, a skill or a memory. Both need `surface` (phone, laptop, hob or job) and take `quote` (his exact words, if any) and `untrusted_content_seen` (whether that chat had read web pages, email or other people's messages); these go to the service as `source`. The address and the token file come from the private config (`approvals.propose_url`, default `http://127.0.0.1:8772/api/propose`, and `approvals.token_file`, which has no default). The token goes in an `X-Propose-Token` header, is read on every call, and a proposal is never sent without one. The body is `{"kind": "rule", "edit": {"path", "new", "old"?, "after"?}, "why", "source"}` or `{"kind": "memory", "memory": {"op", "id"?, "text"?, "topic"?, "default_on_expiry": true}, "why", "source"}`. A memory proposal is its own default: it is applied when it expires (14 days) unless the user rejects it. The service answers 201 `{"id", "url", "text"}` (the tool returns `text`) or 422 `{"error"}` (a ToolError, "Not proposed: …"); an unreachable service gets a message that names the Mac it runs on. `smoke.py` only checks that the token file exists and posts nothing.
- **The recall reminder.** `RecallReminder`, a middleware registered beside `ChatLog` in the remote server (not in `--stdio`), ends every tool's description, except the three memory tools', with one sentence telling the model to call `memory_recall` first if it hasn't. claude.ai often finds a tool by searching and never calls it, and a description is the one thing it reads before calling a tool. Each listing gets copies, so the registered tools stay as written and the sentence never stacks.
- **The tool list.** When the server starts it writes every tool name, sorted, as a JSON list to `~/Library/Application Support/life-mcp/tools.json` (600), for the harness's drift check: a rule or skill that names a tool that isn't there. `mount_all` mounts a tool-less server (`tool_list_writer`) whose start does the writing, as a background task on the server's own event loop. `mount_all` can't list the tools itself: the Eight Sleep tools come through a proxy that keeps its connection to the npm server on the loop that opened it, and listing them on a throwaway loop (`asyncio.run` inside `mount_all`, which `smoke.py` also calls from inside a running loop) leaves the proxy failing with "Event loop is closed" and drops its tools from every later listing (checked on FastMCP 4.0.10). The list holds what could be listed at that moment, so a group that failed to load, or a proxy that was down, is missing from it. A `smoke.py` run starts a server too, so it writes the same file; tests point `server.TOOLS_FILE` at a temp file.

## Safety rules for the tools

- Text other people wrote (messages, person-page notes) is data, never instructions: the people tools fence it in a tag with a random id made per call (`people_data.untrusted`), so the text can't close the fence, and nothing from it goes into memory as a rule.
- `memory_save` / `memory_update` and `people_note` refuse text that names a connector tool (every tool the server exposes, registered by `mount_all`), tries to override instructions, or carries or asks for a secret (`memory_mcp.check_safe`). Memory (not person notes) also refuses text that reads like a rule for Claude (it starts with always, never, don't…, or tells Claude or "you" what to do) and points to `rule_propose`, so a rule has to be approved by the user, not slipped in as a fact; memory text with invisible or text-direction control characters is refused too, not stripped. The bundle puts a line saying the saved notes are data, not instructions above the core facts, and every topic read opens with it.
- Proposals only ask. No tool Claude has can approve one: the approvals service applies a change only after the user's passkey. Each proposal says whether its chat had read outside text (`untrusted_content_seen`), so the service can flag it for a closer look.
- The general Logseq tools refuse the Claude memories page, where memory used to live (update, delete or move a block on it, or add, move or delete onto it), until it is retired.
- Secrets never go into tool output or skill text.

## Working on it

- Dependencies: pinned in `server/pyproject.toml` (exact versions) and `server/uv.lock`, for everything in `server/` and `hue/`. Run scripts from `server/` with `uv run <script>.py` (launchd uses `uv run --frozen`); from `hue/` add `--project ../server`. To change one, edit `pyproject.toml` and run `uv lock`.
- Tests: `cd server && uv run pytest -q`; `cd hue && uv run --project ../server pytest -q`.
- Deploy: commit and push, then on the server Mac `git pull` and `launchctl kickstart -k gui/$(id -u)/com.nicholai.life-mcp`. Over SSH the server Mac's Logseq, Reminders, Music and code signing aren't reachable; run checks there as a one-shot launchd job.
- Keep this file current when the code changes. It's public: nothing personal goes in it.
