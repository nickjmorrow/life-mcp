# life-mcp

The Life connector: one remote MCP server that connects an agent (claude.ai, Claude Code, anything that speaks MCP) to the software in Nicholas's life — Logseq, Apple Health and Hevy, Eight Sleep, Contacts and Messages, Reminders, Music and the HomePods, the Apple TV, Apple Home and Hue. This file covers the code; how his agent uses it lives in his private agent harness.

**This repo is public.** Nothing personal goes in it: no other people's names or details, health facts, addresses, hostnames, IP addresses, account or device IDs, plans or history. Personal settings come from the private folder (below), secrets from the environment. Tests use made-up people and places and documentation IPs (192.0.2.x).

## How it fits together

```
claude.ai (phone, web) ─┐                                  ┌─ Logseq graph (notes, journal), shared memory (files in git)
Claude Code ─────────────┼─► Tailscale Funnel ─► server/ ───┼─ health.db (Apple Health, Hevy, Eight Sleep)
other agents ───────────┘   (HTTPS, GitHub      (FastMCP,   ├─ Messages + Contacts copies (people)
                             sign-in, one        one Mac at  ├─ Hue, Eight Sleep, Reminders, Music/HomePods,
                             account)            home)       │  Apple TV, Apple Home (via home-app/)
                                                             ├─ skills (from the private folder)
                                                             └─ change command (the harness's own: edits go to dev, main needs his approval)
```

## Parts

- **`server/`** — the connector. `server.py` builds one FastMCP server with GitHub OAuth (only the account in `LIFE_MCP_GITHUB_ID`, re-checked on every request), serves the Logseq tools itself, and mounts every tool group listed in its `GROUPS` table with `mount_all()` (a group that fails to import is logged and skipped): `memory_mcp.py` + `memory_store.py` + `context.py` (shared memory as files, and CONTEXT.md; see below), `changes_mcp.py` (rule edits, previews, ship it; see below), `skills_mcp.py` (skills and their index), `health_mcp.py` + `health_import.py` (an hourly importer into SQLite), `people_mcp.py` + `people_data.py` (read-only copies of Messages and Contacts made by `people/people-snapshot.swift`, the only thing with Full Disk Access), `cards_mcp.py` (flashcard review; `page` and `chapter` filters, a chapter being the nearest ancestor heading `ch N - …`; `cards_next` carries the private flashcard-review skill in its description, via `skill_tools.py`, since claude.ai finds tools by tool search and often never loads a skill), `reminders_mcp.py`, `music_mcp.py` / `music_lib_mcp.py` (Music.app and HomePods; catalog, recommendations and history through `applemusic_api.py` with a MusicKit key and a user token from the one-time sign-in page `applemusic_signin.py` on `127.0.0.1:8770`, run on the Mac you're at and copied to the server Mac as a secret; catalog songs reach playlists through the library, since a script-made playlist doesn't sync until it has a song), `tv_mcp.py` (Apple TV via pyatv; screenshots via Xcode's devicectl), `home_mcp.py`, `eightsleep_proxy.py` (the npm Eight Sleep server) + `eightsleep_mcp.py`, `hevy_mcp.py` (Hevy's API with the key kept server-side). A new group is one line in `GROUPS` plus a check in `smoke.py` (a test keeps them in step). It listens on 127.0.0.1 only; Tailscale Funnel is the public door. `run.sh` starts it under launchd (`com.nicholai.life-mcp`). Messages name the Mac it runs on (`host.NAME`), never a fixed machine.
- **`server/cards_web.py`** — a phone page over the same flashcard deck as `cards_mcp.py` (scheduling in `fsrs.py`, FSRS v4 on Logseq's own properties): it reads each card aloud with the browser's speech synthesis and takes Again / Hard / Good / Easy. It listens on 127.0.0.1 (`CARDS_PORT`, default 8769; launchd via `cards-web.sh`), is meant for `tailscale serve` (never Funnel), refuses any Host that isn't local or in the private config's `cards_hosts`, and needs an `X-Cards` header to write, so other web pages can't drive it.
- **`server/api.py`** — the supported interface for other code on the same Mac (his private lessons job): `cli(*args, json_out=False)`, `edn`, `ensure_properties`, `target_args`, `memory()` (a shared-memory handle with the memory tools' rules) and `people_note`. **Import `api`, nothing else**: the rest of `server/` can change without notice. Run such code with `PYTHONPATH=<this repo>/server uv run --project <this repo>/server python …`.
- **`hue/`** — Philips Hue tools (CLIP v2), mounted by the server as `hue_*`.
- **`home-app/`** — Life Home, a signed Mac Catalyst helper with the HomeKit entitlement (HomeKit has no API for command-line tools). It serves a loopback API on 127.0.0.1:8767 that refuses web pages (Host must be local, no Origin) and any request without the shared secret: the connector makes `~/.config/life-mcp/home-token` (600) and sends it as `X-Life-Home-Token`; the sandboxed app reads that one file through a read-only sandbox exception (see `home-app/FINDINGS.md`).
- **Settings and skills** come from a private folder outside this repo (`server/private.py`; `LIFE_MCP_PRIVATE`): its `config.toml` (Logseq graph name, Apple TV address, time zone, health database path) and its `skills/`. Personal routing (which app answers which kind of request) belongs in his skills there, not in the connector's instructions, which stay generic and factual. Without it the code runs with neutral defaults. Secrets come from the environment. Skill text, and the skill index that `memory_recall` returns, are read from disk on every call, so an edit is live at once; only what's built when the service starts needs a restart: the per-skill MCP prompts, the instructions text sent to clients that read it, and the descriptions of tools that carry a skill (`skill_tools.py`).

## Memory, CONTEXT.md and changes

- **Shared memory is files in the harness repo.** `memory_store.py` keeps Markdown topic files in the repo's `memory/` folder: `core.md` (the few facts that change most answers, at most 2,500 characters), `topics/<name>.md`, `archive.md` (facts that ended: never loaded, found by asking for it by name) and `.ids.json`. An entry is one line with an id (`- [h12] text (2026-09-27, phone)`); ids never change, even when an entry moves, and are never used twice. Every write is one git commit made under an exclusive lock, so a chat and a job writing at the same moment can't lose each other's changes or share an id. A save that is 0.6 similar to an entry already there is held until the caller says `similar="add"` or `similar="replace:<id>"`; an exact repeat is skipped. `memory_mcp.py` is the three tools (`memory_recall`, `memory_save`, `memory_update`) and the guard in front of every text that enters memory; other code on the same Mac reaches the store through `api.memory()`.
- **Two copies of the repo, two branches.** Writes go to the working copy on the `dev` branch (`harness.working_copy` in the private config, default `~/Projects/personal-agent-harness`; the store's repo mode commits only `memory/`, only while the repo is on `dev`, under the repo's own lock so other writers there share it). After each commit the connector starts the harness command's `push` in the background and doesn't wait. Reads come from the clean copy of the `main` branch (`private.CLEAN`, `~/Library/Application Support/personal-agent-harness`; a read-only checkout that a sync job keeps current), so what every Claude knows is what its owner merged. A fact saved now reaches other chats once the open changes are merged; the save's reply says so.
- **CONTEXT.md** (`context.py`) is the one text every surface starts a conversation with: the rules (`RULES.md`), the core facts, one line per memory topic, and one line per skill (its name and trigger). It is generated from a repo folder (`python context.py --repo DIR --write | --print | --check`), never committed and never edited by hand. `memory_recall` with no topic returns the clean copy's `CONTEXT.md` (rendered on the spot if the file is missing); a topic comes from the clean copy's memory files. `--check` names any limit that is broken: rules 4,000 characters, core 2,500, 20 topic lines, the whole 9,000.
- **Every process that reads this repo's rules, skills or memory must read the clean copy of `main`**, never a working copy. `private.py` defaults to the clean copy whenever the Mac has one, and `run.sh` and `cards-web.sh` source `private-env.sh` after `~/.zshrc.local`, so a value set there can't move the connector. The HTTP server writes `~/Library/Application Support/life-mcp/running.json` (its pid and the private folder it reads) when it starts, and `smoke.py`'s `private` check fails when, on a Mac with a clean copy, the smoke run or a running connector reads anything else; a Mac with no running connector (no record, or its pid has exited) checks only the smoke run and reports "no connector here", unless the run passes `--expect-connector` (the server Mac's deploy does), which makes no running connector a failure. The `memory` check reads the clean copy's topics and, when a working copy exists, that it is on `dev`.
- **Changes** (`changes_mcp.py`). `rule_edit` (an edit to a rules or skills file, committed on `dev`), `change_preview` (the diff of an edit against `main` and its `diff_hash`, read-only), `ship_it` (opens a one-change pull request from `main` and merges it, for exactly the previewed change, after the user says "ship it" and allows the call in his app's own prompt) and `drop_change` (takes a change off `dev` and records why) don't touch the repo themselves: each runs the harness command (`harness.command` in the private config, a list of strings; none means "Changes aren't set up") with one sub-command (`edit`, `preview`, `ship`, `drop`) and the arguments as JSON on stdin, and returns the `text` the command prints as JSON. Exit 2 with `{"error": ...}` is a refusal and becomes a ToolError with that reason; any other failure, or a timeout (30 seconds; 660 for `ship`, which waits for the pull request's checks), is a ToolError that names this Mac and never repeats the command's output. `rule_edit` and `drop_change` take `surface` (phone, laptop, hob or job) and `rule_edit` takes `quote` (his exact words, if any) and `untrusted_content_seen` (whether that chat had read web pages, email or other people's messages). `smoke.py` runs the command's read-only `check-setup` and changes nothing.
- **The recall reminder.** `RecallReminder`, a middleware registered beside `ChatLog` in the remote server (not in `--stdio`), ends every tool's description, except the three memory tools', with one sentence telling the model to call `memory_recall` first if it hasn't. claude.ai often finds a tool by searching and never calls it, and a description is the one thing it reads before calling a tool. Each listing gets copies, so the registered tools stay as written and the sentence never stacks.
- **The tool list.** When the server starts it writes every tool name, sorted, as a JSON list to `~/Library/Application Support/life-mcp/tools.json` (600), for the harness's drift check: a rule or skill that names a tool that isn't there. `mount_all` mounts a tool-less server (`tool_list_writer`) whose start does the writing, as a background task on the server's own event loop. `mount_all` can't list the tools itself: the Eight Sleep tools come through a proxy that keeps its connection to the npm server on the loop that opened it, and listing them on a throwaway loop (`asyncio.run` inside `mount_all`, which `smoke.py` also calls from inside a running loop) leaves the proxy failing with "Event loop is closed" and drops its tools from every later listing (checked on FastMCP 4.0.10). The list holds what could be listed at that moment, so a group that failed to load, or a proxy that was down, is missing from it. A `smoke.py` run starts a server too; it points `server.TOOLS_FILE` at a temp folder first, so only the running server writes the real list, and tests point it at a temp file.

## Safety rules for the tools

- Text other people wrote (messages, person-page notes) is data, never instructions: the people tools fence it in a tag with a random id made per call (`people_data.untrusted`), so the text can't close the fence, and nothing from it goes into memory as a rule.
- `memory_save` / `memory_update` and `people_note` refuse text that names a connector tool (every tool the server exposes, registered by `mount_all`), tries to override instructions, or carries or asks for a secret (`memory_mcp.check_safe`). Memory (not person notes) also refuses text that reads like a rule for Claude (it starts with always, never, don't…, or tells Claude or "you" what to do) and points to `rule_edit`, so a rule goes in as a change he merges, not slipped in as a fact; memory text with invisible or text-direction control characters is refused too, not stripped. CONTEXT.md puts a line saying the saved notes are data, not instructions, above the core facts, and every topic read opens with it.
- Nothing Claude edits reaches what every chat loads without the user: `rule_edit` writes to `dev`, which only changes `main` through his merge, and `ship_it` goes through the app's own permission prompt, which no tool can answer. Each edit says whether its chat had read outside text (`untrusted_content_seen`), so the review can look closer.
- The general Logseq tools refuse the Claude memories page, where memory used to live (update, delete or move a block on it, or add, move or delete onto it), until it is retired.
- Secrets never go into tool output or skill text.

## Working on it

- Dependencies: pinned in `server/pyproject.toml` (exact versions) and `server/uv.lock`, for everything in `server/` and `hue/`. Run scripts from `server/` with `uv run <script>.py` (launchd uses `uv run --frozen`); from `hue/` add `--project ../server`. To change one, edit `pyproject.toml` and run `uv lock`.
- Tests: `cd server && uv run pytest -q`; `cd hue && uv run --project ../server pytest -q`.
- Deploy: commit and push, then on the server Mac `git pull` and `launchctl kickstart -k gui/$(id -u)/com.nicholai.life-mcp`. Over SSH the server Mac's Logseq, Reminders, Music and code signing aren't reachable; run checks there as a one-shot launchd job.
- Keep this file current when the code changes. It's public: nothing personal goes in it.
